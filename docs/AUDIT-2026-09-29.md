# Seller Net Waterfall — Repository Audit

Date: 2026-09-29
Base audited: `main` at `4b054c8fc9f9c06ef078a66209d37da1b0c39b73`
Hardening branch: `audit-hardening-2026-09-29`

## Confirmed strengths

- Canonical financial engine is isolated in `src/frontend/src/lib/seller-net/calculator.ts`.
- UI and MCP layers delegate calculations to the canonical engine.
- HECM, Section 121, friction, scenarios, provenance, snapshots, charts, client view, and print view have dedicated regression coverage.
- Run records are owner-scoped in the backend by authenticated principal.
- MCP transport is separated from handlers/service logic.
- No hard-coded bearer secrets were found in the MCP layer.
- Caffeine export includes extensive contract tests and a provider-neutral MCP service boundary.

## Confirmed issues fixed on this branch

1. **Estimated mortgage UNKNOWN handling**
   - ESTIMATE mode with a positive balance could silently treat UNKNOWN rate/months as zero.
   - Validation now requires both rate and months for positive-balance estimated payoffs.

2. **Professional-review domain mismatch**
   - Canonical output omitted ESCROW and TITLE even though they are baseline review domains.
   - Canonical results now include ESCROW + TITLE, adding LENDER and CPA_TAX contextually.

3. **MCP stored-run authorization**
   - `seller_net.explain_result` could load a stored run without requiring the run-record scope.
   - `runId` explanations now require `seller_net:runs`.

4. **Weak MCP structural input guard**
   - MCP previously checked only that SellerNetInput keys existed.
   - It now validates provenanced field structure, finite numeric/null values, provenance enums, canonical enums, booleans, and rejects unexpected top-level keys.

5. **Weak MCP discovery schema**
   - The advertised SellerNetInput schema did not enumerate canonical fields.
   - Tool discovery now exposes concrete provenanced fields and enum contracts.

6. **Ignored MCP explicit scenario targets**
   - `targets` were validated but not used.
   - Explicit downside/current/upside targets now run through the canonical scenario calculator.

7. **CI missing**
   - Added GitHub Actions frontend typecheck + regression workflow.

## Open issues / next hardening pass

### High priority

- **Computed non-finite values are coerced to zero in the calculator.**
  `roundMoney()` and `sanitizeOutput()` prevent NaN/Infinity from reaching the UI by converting them to 0. That is safe for rendering but can mask a failed financial computation as a legitimate zero. Boundary validation should make invalid computations unreachable, and calculator-level failure semantics should be made explicit without breaking the live draft-preview UX.

- **Saved-run replay is version-blind.**
  Stored records carry `calculatorVersion`, but the Saved Runs page loads inputs into the current calculator with no version-mismatch warning. Add explicit mismatch metadata/warnings before treating historical replay as identical.

- **Saved-run JSON replay parser is shallow.**
  `parseEffectiveInputs()` validates only a few top-level shapes before casting to `SellerNetInput`. Reuse a canonical strict SellerNetInput shape guard.

- **MCP production transport is not publicly reachable.**
  The framework-free MCP layer is real, but Caffeine does not expose the required public remote endpoint. A thin public Streamable HTTP adapter is still required on a deploy target that supports it.

### Medium priority

- **Original dark/light persistence spec remains unimplemented.**
  `next-themes` is installed, but no theme provider/toggle is wired.

- **Repository contains generated build artifacts.**
  `dist/`, backend wasm/build outputs, and `.old/` are tracked even though related paths are ignored. Decide whether Caffeine requires these artifacts before cleaning history/tracking.

- **Template metadata remains.**
  Root/frontend package names and Caffeine project metadata still contain generic template values such as `my-app`.

- **MCP auth semantics for invalid bearer tokens are lossy.**
  Invalid/expired tokens currently fall back to anonymous context. Protected calls therefore surface UNAUTHORIZED instead of distinguishing invalid credentials as FORBIDDEN. Decide desired public-tool behavior before changing.

- **MCP run-store adapter remains host-specific work.**
  The service defines a clean `RunRecordStore` port, but an external public MCP deployment still needs a production adapter (ICP backend, Postgres/Supabase, etc.).

## Financial-model issues intentionally not changed

These are specification/model questions, not implementation drift:

- Standard mortgage ESTIMATE uses the supplied simple-interest-over-months formula.
- HECM written formula produces approximately 844,939.45 for the locked vector; the older 844,484.77 benchmark is contradictory.
- Market/time friction is deliberately conservative and does not recalculate percentage transaction costs at the discounted sale price.

Do not silently alter these formulas without a deliberate calculator-version change.
