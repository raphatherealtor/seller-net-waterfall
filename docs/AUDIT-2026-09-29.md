## Confirmed issues fixed on this branch

### Calculator and validation

1. **Estimated mortgage UNKNOWN handling**
   - Positive-balance ESTIMATE mode could treat UNKNOWN rate/month values as zero.
   - Estimated payoff now requires both rate and months; VERIFIED_PAYOFF remains exempt because those fields are unused.

2. **Professional-review domain mismatch**
   - Canonical output omitted baseline ESCROW and TITLE review domains.
   - Every result now includes ESCROW + TITLE, HECM additionally adds LENDER, and active tax additionally adds CPA_TAX.

3. **Preview-safe vs authoritative calculation failure semantics**
   - The live work surface still uses a resilient preview calculation so incomplete typing cannot crash the UI.
   - New `calculateSellerNetWaterfallStrict()` uses the same formulas but throws instead of converting a failed/non-finite authoritative computation into a legitimate-looking zero.
   - MCP calculations and saved snapshots use the strict path.
   - Extreme HECM overflow now fails closed in authoritative flows.

### MCP contract and security

4. **Stored-run authorization bypass**
   - `seller_net.explain_result` could load a stored run by `runId` without run-record scope.
   - Stored-run explanations now require `seller_net:runs`.

5. **Strict SellerNetInput runtime validation**
   - MCP formerly checked primarily that required keys existed.
   - A shared canonical runtime guard now validates exact keys, nested provenanced-number shape, finite number/null values, provenance states, enums, and booleans.
   - Saved-run replay uses the same guard instead of a shallow cast.

6. **Strict SellerNetOutput runtime validation**
   - Stored output JSON and externally supplied `explain_result` payloads were previously trusted after shallow object checks.
   - A canonical output guard now verifies the complete finite output contract and professional-review domain vocabulary.
   - Malformed historical output JSON is shown as unavailable rather than rendered as financial figures.

7. **MCP discovery schema quality**
   - Tool discovery previously advertised SellerNetInput as a generic object.
   - Discovery now exposes concrete canonical fields, provenanced-number structure, and enum contracts.

8. **Explicit scenario targets were validated but ignored**
   - `seller_net.compare_scenarios` now actually uses the requested downside/current/upside target prices.
   - Explicit target mode requires exactly three prices and preserves structured range/count errors.

9. **Advertised numeric limits were not fully enforced**
   - MCP now enforces its published money and accrual-month bounds on SellerNetInput, in addition to canonical semantic validation.

10. **Invalid bearer credentials collapsed into anonymous**
    - Missing credentials remain UNAUTHORIZED for protected tools.
    - Presented-but-invalid credentials remain distinct and produce FORBIDDEN.
    - Valid scoped credentials continue normally.

11. **Health could report OK while persistence was down**
    - `seller_net.health` now reports degraded unless both calculator and persistence dependencies are available.

### Saved runs and user experience

12. **Historical replay was version-blind**
    - Stored runs now expose version mismatch metadata.
    - The UI warns when a historical snapshot was created under another calculator version and labels the action Recalculate rather than implying identical replay.

13. **Dark/light persistence was unfinished**
    - Existing dark CSS tokens are now activated through `next-themes`.
    - Appearance follows system by default, can be toggled in the top navigation, and persists under `seller-net-theme`.

### Persistence and delivery hardening

14. **Backend snapshot payloads were unbounded**
    - Motoko run-record validation now bounds identifiers and stored JSON payload sizes in line with the integration boundary.

15. **Independent CI was missing**
    - Added GitHub Actions typecheck + frontend regression CI.
    - Pinned pnpm 9.15.9 after CI exposed incompatibility with pnpm 12's build-script approval behavior.

## Remaining production gates

### 1. Rebuild and verify the Motoko backend in the real Caffeine/PocketIC environment

The hardening branch changes `src/backend/lib/run-records.mo`, so the tracked backend WASM is no longer sufficient evidence for that source revision.

The repository's PocketIC runner deliberately requires Caffeine's sidecar and will skip rather than fabricate a backend verdict when that infrastructure is unavailable. Plain GitHub Actions therefore cannot honestly certify the Motoko change.

Before merge/deploy:
- rebuild the backend from this branch in the Caffeine environment;
- regenerate any derived backend artifact/declarations that the platform owns;
- run the real backend/PocketIC lane;
- verify owner isolation, save/list/get/delete, duplicate rejection, and new payload-size rejection.

### 2. Public remote MCP hosting

The provider-neutral MCP service and JSON-RPC transport are implemented and tested, but the Caffeine app does not itself expose the public Streamable HTTP endpoint needed by remote MCP clients.

A production MCP deployment still needs:
- a public HTTPS endpoint;
- a host adapter around `createMcpTransport`;
- a production token verifier;
- a production `RunRecordStore` adapter if persisted runs are exposed remotely;
- deployment secrets/configuration outside source;
- end-to-end remote client tests.

### 3. Snapshot attestation model

The ICP backend intentionally stores run snapshots as opaque client-submitted JSON. Owner isolation and structural/size validation are enforced, but the backend does not independently recompute the financial result.

Therefore a stored run is currently:
- an immutable owner-scoped client-authored snapshot;
- **not** a server-attested proof that its output/hash/version came from the canonical calculator.

If stronger audit guarantees become a requirement, that should be designed explicitly rather than implied by the current storage model.

## Deferred cleanup decisions

These are not correctness blockers and should not be changed blindly because they may be part of Caffeine's generated-project workflow:

- generic template package/project metadata such as `@caffeine/template-app`, `@caffeine/template-frontend`, and `my-app`;
- tracked generated `dist/`, backend WASM/build output, and `.old/` artifacts;
- Node 20 in the CI setup currently works, though GitHub Actions emits a platform deprecation warning;
- richer field-specific min/max annotations could be added to MCP discovery schemas beyond the runtime enforcement already present.

## Financial-model decisions intentionally unchanged

These are model/specification decisions, not implementation drift:

- Standard mortgage ESTIMATE continues to use the supplied simple-interest-over-months formula.
- The written HECM formula produces approximately `844,939.45` for the locked vector; the older `844,484.77` benchmark is contradictory and is not forced into the engine.
- Market/time friction remains deliberately conservative and does not recalculate percentage transaction costs at the discounted sale price.

Do not silently alter these formulas. Any intentional formula change should receive a deliberate calculator-version change and new locked regression vectors.
